# IoT Current Scope desktop application

**Version 1.0.0 · In development**

Created by **Wenderson Oliveira** as part of [Open Source Current Profiler](https://github.com/wnoliveira/openSource-CurrentProfiler). The application displays one INA219 current channel from the ESP32, records validated readings and exports the visible trace. It also includes a simulated source for exploring the controls without hardware.

The [main README](../README.md) explains wiring, conversion to current, range selection, averaging, calibration and measurement limits. Read that before connecting a load.

## Run on Windows

Double-click `run_windows.bat`, or open PowerShell in this folder:

```powershell
.\run_windows.bat
```

For a simulated load:

```powershell
.\run_windows.bat --demo
```

The launcher uses Python 3.12 x64 from `.python312` when available, otherwise `py -3.12`. It creates `.venv` and installs `requirements.txt` if needed. The first dependency installation needs internet access.

To prepare the environment yourself:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --demo
```

In VS Code, select `.venv\Scripts\python.exe` under **Python: Select Interpreter**. Source execution on Linux uses the same requirements and `python main.py`; the included launch and build batch files are specific to Windows.

## Language, theme and project information

The **Language** selector offers **System default**, **English** and **Português**. A fresh installation follows the system language: Portuguese on a Portuguese computer and English for English or unsupported computer languages. A manual choice is remembered and applies immediately, including during acquisition; no restart is required.

The application opens maximized with the dark theme by default. Light and dark themes change both the controls and the plot, including the **About** and **Licenses** dialogs. The selected theme is remembered between runs. The **About** dialog includes the version, development status, **Created by: Wenderson Oliveira** and a link to the [GitHub repository](https://github.com/wnoliveira/openSource-CurrentProfiler). **Licenses** opens the bundled project and third-party notices.

On close, the application saves acquisition choices, shunt resistance, display units and scales, trigger settings, calibration reference, selected port and panel layout. Reopening restores these preferences without connecting or starting acquisition. If restored sensor choices differ from the connected device, click **Apply settings** and wait for acknowledgement before starting. Calibration coefficients remain on the ESP32.

## First measurement

1. Flash the ESP32 with the current firmware, connect it by USB and close other serial monitors.
2. Select the port and connect. Confirm the intended INA219 address; detection is a plausibility check, not chip identification.
3. While stopped, enter the actual shunt resistance and select PGA, rate and averaging. Apply the configuration and wait for acknowledgement.
4. Remove the load and run zero calibration. Use a suitable known-current reference for gain calibration when needed.
5. Start acquisition. Sensor settings and shunt resistance are locked during the session; display scales, units and trigger remain adjustable.
6. Start continuous CSV capture to record the session. Stopping capture closes its file while acquisition continues. Stopping acquisition also closes capture.

In DEMO mode, start acquisition to see a synthetic pulsed load. Its timestamps and measurements are generated by the simulator. It tests the software path without establishing sensor performance.

## Finding the controls

| Area | Purpose |
|---|---|
| Connection and acquisition bar | Select a serial port or DEMO, connect, start, stop and pause the display. |
| Acquisition tab | Address, PGA range, rate, averaging and shunt resistance. Changes require Apply. |
| Display tab | Units, time/division, current/division, vertical center, trigger and pre-trigger. |
| Calibration tab | Zero, known-current gain correction and reset for the selected PGA. |
| Files tab | Continuous CSV recording and visible-trace CSV/PNG export. |
| Diagnostics | Received/missing packets, CRC errors, device counters and event log. |

The plot has ten horizontal and eight vertical divisions. Time/division and current/division use 1–2–5 steps across decades. Other numerical controls use adaptive decimal steps. Values can be typed directly. The mouse wheel does not change settings accidentally. Drag the divider to adjust the control panel width.

| Shortcut | Action |
|---|---|
| F5 | Start acquisition after configuration is accepted. |
| F6 | Stop acquisition. |
| F7 | Pause or resume the display. Acquisition and recording continue. |
| Ctrl+0 | Fit the vertical scale to the displayed points. |
| F11 | Toggle full-screen mode. |
| Esc | Leave full-screen mode. |

The software trigger supports Free, Auto, Normal and Single modes, rising or falling edges, and 0–90% pre-trigger. Click inside the plot to select the trigger level and position, or drag the horizontal line to change the level and the vertical line to change pre-trigger. The fields and plot markers stay synchronized. These adjustments are available in Auto, Normal and Single modes. It aligns samples already received by the computer; it does not trigger the ADC. A gap in sequence breaks the trace. See the [measurement explanation](../README.md#display-and-trigger) for the implications.

## Files and time

Continuous capture saves all accepted incoming samples after recording starts. Screen CSV saves the acquired points inside the displayed window. PNG saves the plot in its current theme. A `.csv.json` file next to each CSV records the settings used to interpret the session.

Raw readings remain available alongside corrected current, shunt resistance and calibration coefficients. Device time marks the end of the ESP32 I²C read. Estimated UTC is based on the computer clock at START acknowledgement; it is not an externally synchronized timestamp.

A recording error, STOP or disconnection closes the capture. If the board resets or the active serial link goes silent, inspect diagnostics and reconnect before starting a fresh session.

## Build a Windows executable

Use Windows and Python 3.12 x64. Double-click `build_windows.bat`, or run:

```powershell
.\build_windows.bat --no-pause
```

The script prepares `.venv`, checks dependencies and creates a PyInstaller single-file executable in a staging folder. Before replacing a previous build, it runs that executable in an isolated working directory with DEMO acquisition, SVG loading and CSV/PNG export checks. The previous executable is retained if the build or self-test fails.

| Output | Purpose |
|---|---|
| `dist/IoTCurrentScope.exe` | Application; Python need not be installed on the destination computer. |
| `dist/IoTCurrentScope-source.zip` | Application sources, assets, build scripts and notices needed to rebuild it. |
| `dist/self-test.json` | Result of the packaged application's self-test. |
| `build/build_windows.log` | Detailed build and test diagnostics. |

Close a running copy before rebuilding. First startup of a single-file package may take longer because it extracts libraries into a temporary directory. A CP210x driver may still be required for the board.

```powershell
.\dist\IoTCurrentScope.exe --demo
```

To repeat the packaged check without a visible window:

```powershell
cmd /c 'start "" /wait "dist\IoTCurrentScope.exe" --self-test "%CD%\build\self-test.json"'
Get-Content .\build\self-test.json
```

Startup failures are written to `%LOCALAPPDATA%\IoTCurrentScope\startup.log`; the startup error dialog identifies that path.

## Tests

From this folder:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

From the repository root:

```powershell
.\desktop\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\desktop\.venv\Scripts\python.exe -m unittest discover -s desktop/tests -v
```

These checks cover protocol handling, current conversion, timing planning, trigger behavior and the Qt interface with a simulated source. They do not replace a measurement on the ESP32. Current results and remaining bench work are recorded in [VALIDATION.md](../VALIDATION.md).
